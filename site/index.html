Lint the accessibility of standalone SVG files

iconlens computes the accessible name of a standalone .svg file the way a screen reader would: aria-labelledby, then aria-label, then the first child <title>. It flags the structural failures that break the name.

iconlens is written in TypeScript, runs on Bun, and is MIT licensed. It parses files on disk, runs in CI, and emits text, JSON, or SARIF 2.1.0 for GitHub code scanning. It does not use a browser or make network requests.

Existing tools do not lint standalone SVG

Design systems and icon libraries ship .svg assets with no accessible name. The tools commonly used for SVG do not catch it.

svglint

A generic XML and attribute linter. It checks accessibility only if you hand-write the rules, and it has no accessible-name computation or dangling-IDREF checks.

github.com/simple-icons/svglint →

svgo

Actively removes <title> and <desc> by default, so its default preset strips the accessible name out of the asset.

github.com/svg/svgo →

axe-core / Pa11y

Need a live DOM and a browser, so they cannot lint an asset file sitting on disk before it ships.

github.com/dequelabs/axe-core →

Biome noSvgWithoutTitle

A single rule that only covers inline HTML or JSX. It never sees a standalone .svg file on its own.

biomejs.dev →

W3C ACT 7d6734

Defines the accessible-name test precisely, but ships no implementation you can actually run in CI.

w3.org ACT rule 7d6734 →

What iconlens does

A small offline binary that understands SVG accessibility structure, not just XML well-formedness.

SVG-AAM name computation

Resolves aria-labelledby, then aria-label, then the first child <title>, and stops at the first source that applies, as the spec orders it.

Structural rules

Missing names, dangling IDREFs, duplicate ids, leftover tabindex, misplaced <title>, and more, with a WCAG reference on every finding.

Offline by design

Files are parsed locally, with no network code, uploads, or telemetry. It runs the same on a laptop, in a container, or in air-gapped CI.

CLI and library

Lint files or directories from the command line, or call auditSvg directly from TypeScript. The same rules power both.

SARIF 2.1.0

Emit a SARIF log so findings surface inline in GitHub code scanning and the Security tab, with severity mapped to SARIF level.

CI gate

Exits 1 on any error-severity issue, 0 otherwise, and 2 on bad usage. --fail-on tightens or loosens the threshold.

How a file is checked

The pipeline is static and has no rendering step.

  1. 1

    Parse

    fast-xml-parser builds a node tree, an id map, and the list of duplicate ids in one pass.

  2. 2

    Compute the name

    Resolve aria-labelledby, then aria-label, then the first child <title>, stopping at the first source that applies.

  3. 3

    Run the rules

    Eight rule functions read the tree and emit issues, each with a severity and a WCAG reference.

  4. 4

    Report

    Print text or JSON, write SARIF 2.1.0, and exit 0, 1, or 2 for CI.

The eight rules

Accessible-name computation is the core. Each rule describes a specific way a standalone graphic breaks.

Accessible-name priority (SVG-AAM)

iconlens follows the SVG-AAM priority order and stops at the first source that applies.

  1. 01

    aria-labelledby

    Each referenced id is resolved and its text concatenated, in order. A reference to a missing id is itself a finding (SVG-NAME-002).

    wins
  2. 02

    aria-label

    Used when no aria-labelledby applies and the attribute carries text.

  3. 03

    <title>

    The first child <title> of the root <svg>. A title anywhere else is flagged (SVG-TITLE-004).

The first source that yields a non-empty name wins; the rest are ignored. If none apply, the graphic has no accessible name — and the rules say so.

<svg xmlns="http://www.w3.org/2000/svg" role="img" aria-labelledby="t">
  <title id="t">Company logo</title>
  <path d="…" />
</svg>

Install

iconlens is not published to npm. Install it with the one-line script, or run it without installing.

# One-line install (installs the `iconlens` binary)
curl -fsSL https://raw.githubusercontent.com/srivtx/iconlens/main/install.sh | sh

# Or run once, without installing
bunx github:srivtx/iconlens icons/*.svg

# Install globally
bun add -g github:srivtx/iconlens
iconlens icons/*.svg

# Add to a project as a dev dependency
bun add -d github:srivtx/iconlens

CLI and library usage

The same rule set runs from the command line or from TypeScript.

iconlens <files…>
Lint one or more .svg files.
--dir <path>
Lint every .svg file under a directory.
--json
Print a machine-readable JSON report to stdout.
--quiet
One summary line per file.
--sarif <file>
Write a SARIF 2.1.0 log for GitHub code scanning.
--fail-on <level>
error (default), warning, info, or none — sets the exit-code threshold.
# Lint files
iconlens icons/*.svg

# Lint a directory
iconlens --dir icons/

# Machine-readable
iconlens logo.svg --json

# One summary line per file
iconlens logo.svg --quiet

# SARIF for GitHub code scanning
iconlens logo.svg --sarif iconlens.sarif

# Choose when the exit code becomes non-zero
iconlens logo.svg --fail-on warning

Or call it as a library:

import { auditSvg, accessibleName, parseSvg, toSarif } from "iconlens";

const result = auditSvg(source, "logo.svg");
const name = accessibleName(parseSvg(source));
// { name: "Company logo", source: "aria-labelledby" }

const sarif = toSarif(result, "iconlens", "0.1.0");

Exit code is 1 on any error-severity issue, 0 otherwise, and 2 with no arguments. --fail-on defaults to error and also accepts warning, info, or none.

SARIF and GitHub code scanning

Emit a SARIF 2.1.0 log and let GitHub code scanning annotate the pull request.

- name: Icon accessibility scan
  run: iconlens --dir src/assets/icons --sarif iconlens.sarif

- name: Upload SARIF
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: iconlens.sarif

Each issue becomes a SARIF result with ruleId set to its rule code (for example SVG-NAME-001), a level mapped from severity (error → error, warning → warning, info → note), and a location pointing at the file. --fail-on affects only the exit code; every issue is still reported and included in SARIF output.

Limitations

Static analysis

iconlens is static file analysis. It does not render the graphic, so it cannot compute colour contrast. Name computation follows the SVG-AAM priority order but does not implement every edge of the full specification. Inline SVG in HTML or JSX is out of scope.

FAQ

Does it need a browser or a network?

No. iconlens parses files locally, with no network code, uploads, or telemetry. It runs the same on a laptop, in a container, or in air-gapped CI.

How is the accessible name computed?

Per SVG-AAM priority: aria-labelledby first, then aria-label, then the first child <title>. The first source that yields a non-empty name wins; the rest are ignored.

Can it check inline SVG in HTML or JSX?

No. iconlens targets standalone .svg assets on disk. Inline SVG in markup is out of scope; use an HTML or JSX linter for that.

Does it replace axe-core or Pa11y?

No. It complements them. Browser engines test a rendered DOM; iconlens tests the asset before it reaches the DOM, which is the gap they cannot cover.

How do I fail CI on warnings too?

Run iconlens icons/*.svg --fail-on warning. It affects only the exit code; every issue is still reported and included in SARIF output.

What do the exit codes mean?

1 on any error-severity issue, 0 otherwise, and 2 on bad usage such as no arguments.
